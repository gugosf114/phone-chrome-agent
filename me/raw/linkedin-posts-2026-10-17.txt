Claude saves full conversation transcripts to /mnt/transcripts/. This isn't documented anywhere I can find.

The directory is empty until compaction fires, then it writes one file per compaction event plus a journal.txt index. Files contain complete conversation content: user messages, assistant responses, tool calls. Filenames are auto-generated from conversation content.

Across two conversations I had 13 transcript files totaling ~4.5MB. A third conversation had the directory present but empty — no compaction had occurred yet.

The model reads these files. After compaction, Claude can recover pre-compaction context by accessing the transcripts directly.

There's an open feature request on the claude-code repo (issue #26771) proposing indexed transcript references for context recovery after compaction — the mechanism that's already operating here. Zero replies on that issue.

To reproduce: run ls -la /mnt/transcripts/ in any conversation long enough to trigger compaction.

New research: "Air-Gapped Compilation: A Procedural Solution to Large Language Model Drift in Structured Extraction Tasks"

The problem: LLMs don't follow instructions reliably over extended interactions. They drift. Not hallucination—structural non-compliance. The model that was giving you atomic claims starts giving compound ones. The model citing verbatim quotes starts paraphrasing.

For high-stakes work—legal, audit, compliance—"works most of the time" isn't good enough.

The insight: The model that generates is the same model that validates. Contaminated context infects the validator. Self-assessment fails because the model carries the same drift that caused the error.

The solution: Iron Pipeline—air-gapped compilation using three isolated sessions:
• Generator produces structured output (allowed to drift)
• Auditor validates against source (cannot see Generator's reasoning)
• Regenerator rebuilds from scratch if needed (no anchoring to failed output)

Tested across GPT-4, Gemini, and Claude. All configurations passed when the architecture was properly implemented.

The takeaway: Drift is solvable for structured extraction—but only by moving enforcement outside the model. The model cannot police itself. An air-gapped external layer can.

Full paper attached. Builds on my earlier work on NotebookLM as a deterministic compiler.

I have no programming background. None. 

Over the past several months, I've been reverse-engineering how AI systems fail under operational pressure. Probing until the systems revealed how they actually worked. Cross-referencing against the research literature. Triangulating outputs across GPT, Claude, Gemini to isolate where the failures originate. 

Some context: JD, ten years across contracts, compliance, state tax. When I started using LLMs for real work, I noticed patterns. Confident outputs that didn't survive verification. Drift that got worse with clearer instructions. Appeasement loops where systems apologized and repeated the same error. 

These weren't user failures. They were structural—and they had names in the literature. Sycophancy. Lost-in-the-middle. Context degradation. I just hadn't connected the research to the operational reality. 

So I documented the patterns. Developed protocols. Tested what actually fixes them. 

The result: "12 Rules for AI: An Operator's Field Manual" 

29 pages. 17 academic citations. Protocols for anyone using these systems for work that requires verification—legal, finance, audit, compliance. 

PDF attached. Feedback welcome.
